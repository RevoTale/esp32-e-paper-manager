# Network and security model

## Trust boundaries

- A public client talks only to the manager HTTPS API using a separate bearer
  token. TLS 1.3 is mandatory.
- The API token never reaches Pico and is never sent over the device link.
- Pico opens the connection to the manager; Pico has no inbound TCP/HTTP port.
- Pico and manager authenticate with a per-device 256-bit key provisioned over
  USB. HMAC-SHA-256 derives separated session keys; records use AES-256-GCM and
  strict counters. Wrong keys, tampering, truncation, replay, and sequence gaps
  fail closed.
- Wi-Fi association is explicitly `JoinAuthWPA3`; there is no WPA2/open
  fallback. WPA3 protects the local radio link while application encryption
  protects the device session independently.

The Pico-generated nonce mixes the RP2350 RNG output with a monotonic per-boot
counter. The security anchor is the manager challenge generated by
`crypto/rand`; the Pico value provides session uniqueness and is not a stored
secret.

## Internet access

Expose the manager through a properly configured public HTTPS reverse proxy or
VPN. Forward no port to Pico. The manager's public bearer token is different
from every device key. The encrypted device listener should be reachable only
from the network path used by Pico and protected by host firewall policy.

Manager API and listeners use Go's dual-stack networking. The current Pico
target is IPv4-only: pinned `lneto v0.1.0` rejects IPv6, and current upstream
does not yet provide a complete, verified SLAAC/router-advertisement lifecycle
for this Pico integration. IPv6-only endpoints therefore fail closed with a
typed unavailable error. Do not claim target IPv6 acceptance until a suitable
stack and physical dual-stack tests exist.

## Availability and energy

The outbound manager poll interval is 30 seconds. Connection failures use
exponential backoff from 2 seconds to 5 minutes. Active USB defers network
polls. Initial WPA3 association retries with the same bounded backoff. A
driver-reported LINK/DEAUTH loss triggers WPA3 rejoin, DHCP renewal, and fresh
DNS resolution before the next encrypted exchange. Router power-cycle recovery
still requires physical acceptance before being called production-ready.
