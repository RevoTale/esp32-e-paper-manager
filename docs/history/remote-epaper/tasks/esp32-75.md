Authority: REQUIREMENTS-v2, ADR-013/014 and root docs/esp32-port.md.
C dependencies and WPA2 are permitted for ESP32 only. No new commit requested.

## Preserve and reuse

- Preserve Pico/Pi5 code, pins, artifacts and their security policy.
- Preserve experiment12's accepted panel75-check.bin and its exact SPI adapter.
- Go manager renders bounded HTML/inline CSS and images; MCU receives resolved
  pixels, not HTML, CSS, PNG or a browser. Reuse engine and timestamp composition.
- Reuse EPS2 bounds, integrity, status, no-blind-replay semantics and EPN2 mutual
  HMAC authentication/AES-GCM records. Do not create another image protocol.
- Reuse provision/epochstore/network.Lifetime once a real persistent block
  backend passes. No volatile epoch, fixed nonce or successful-write stub.

## Storage reservation — approved; native backend pending

Approval, 2026-09-12: after explaining persistent Wi-Fi configuration, keys and
boot epochs, the user confirmed: "добре, роби як треба, ціль готова прошвика по
тим бажанням". Implement this ESP32 adapter; do not ask for the same storage
approval again. This does not waive native safety or physical acceptance gates.

Reserve the final four 4096-byte sectors of the verified 4-MiB chip:
`[0x3fc000, 0x400000)`. First two sectors hold the existing credential journal;
last two hold monotonic boot epochs. These are approved reserved physical
offsets; linker enforcement and actual flash I/O remain to be verified.

The proposed ESP32-only C/Go adapter must prove IRAM/DRAM residency while flash
cache is disabled, serialize access against radio/interrupts, restore cache
state, check every result and read back changes. Verify the exact Espressif ROM
or supported driver APIs before choosing the implementation. ESP32-C3 addresses
and Pico's interrupt wrappers are not transferable. If that cannot be verified,
stop and propose a supported backend rather than implementing guessed calls.

Reject firmware images intersecting the reserved range. Preserve storage on
ordinary updates. Invalid existing data enters physical-USB recovery, never
automatic formatting. Any destructive initialization requires explicit consent;
recovery erases credentials before epochs and requires fresh enrollment keys.
Protects accidental counter reuse, not hostile physical flash rollback.

## Transport and power constraints

- CH343P is USB-to-UART. Prove its RX budget and connection/session detection;
  an always-true DTR adapter would permanently disable Wi-Fi. Raw boot/radio
  logs must never corrupt binary replies. Never print SSID, passphrase or keys.
- The existing 480-byte USB payload cap was derived from Pico CDC's 512-byte
  ring. It is not automatically safe for ESP32 UART. Negotiate/test limits
  against the installed UART ring, including provisioning records.
- Preserve the shared secure-session protocol. WPA2 admission is explicit and
  ESP32-specific; no open/WPA1/TKIP fallback or reinterpretation of WPA3 as WPA2.
- Device dials the manager and waits for server updates. No public inbound MCU
  endpoint. Manager remains HTTPS/VPN accessible; native device IPv6 is deferred.
- Group/render on the manager, retain optional debounce/max_wait, configurable
  last-full-refresh timestamp policy and bounded firmware safety limits.
- Full refresh is the accepted baseline. Do not copy Pi5 V4 partial commands or
  claim one-second partial refresh on this 7.5 panel without its own acceptance.
- Rev3 software rail cutoff is unverified (R35 NC). Controller power-off/sleep
  is not electrical disconnection. Hardware faults latch and must explicitly
  request manual power removal until safe recovery is proven.
- Controller-RAM streaming remains a separate acceptance gate on this board.
  Bound powered staging and verify aborted uploads never refresh. Do not add
  frame buffers or claim RAM/energy savings without the required measurement.
